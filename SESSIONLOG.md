# Session log

One bullet per commit, oldest first: what changed and how.

- Development CI no longer requires an uploaded riscv64 wheel artifact; green required jobs on the exact head are enough, as the CI policy says.
- A new fork head during handoff is observed again instead of keeping the old waiting state, because a new head clears old readiness.
- A worker's valid no-change answer is accepted instead of being counted as a validation failure, and a Result of Work that was withdrawn or already answered is recorded as late instead of folded.
- Running out of repair attempts parks the contribution, and resume from parked starts a new generation, both following the table.
- The site uses the Just the Docs theme and renders `docs/`, and the Website workflow builds previews of same-repository pull requests under `/pr/<N>/`.
- The generated status page moves to its own `/status/` page so the site home describes the project.
- Adds the mandatory repository rules for every change (docs in sync, no milestone wording, no AI mention in commits, no U+2014, fix the pipeline not the resources).
- Renames every workflow to a title-cased name without the prefix and updates the controller's workflow_run triggers and the dossier comment check that match on those names.
- The Pages artifact wait now queries the same artifact store `deploy-pages` reads and retries the deploy with backoff, fixing preview deploys that failed on a race.
- Adds the lifecycle table in `lifecycle.py` as the single source of truth, a `lifecycle check` consistency check run in CI, and docs pages generated from it.
- Applies the operator's decisions on the open state-machine questions to the table, its budgets, its checks and the generated decisions page.
- Adds `engine.py`, the single write path that applies table rows, a compatibility layer for unconverted code, and an evented migration that moved the live record to `handoff.awaiting_submission`.
- The tracking-issue ledger asks for the exact `submit-upstream` command when a contribution reaches the submission gate.
- A worker Result for a stopped contribution or for Work no longer requested takes `record_late_effect` instead of crashing the tick.
- Park, abandon and pause clear a pending publication so resume and restart are never blocked forever, and publish retries stop while paused.
- Applies six operator decisions to the table and engine: Work carries its feedback, the gate records reviews and explanations, per-head rerun counts, and patch versus repair admission.
- Adds a Known gaps page listing where code does not yet follow the table, and an AGENTS.md rule to keep it current.
- An unexpected error in one contribution discards only its staged changes and pauses it, while transient GitHub read failures just skip it for the tick.
- Pause, resume, park and refresh go through the engine in every table state, `block` is merged into `paused`, and existing records are migrated.
- The controller posts `record_reminder` at gate and human-wait states on the policy's business-day interval.
- Adds the stop and reminder gaps found in review to the Known gaps page.
- Retires the commands the table removed with replies naming their replacement, and replaces the old terminal phases with `closed.idle` plus `terminal_reason`.
- The replies for retired `provision` and `clarify` name park then resume, which actually works in a provisioning wait.
- Work ids include the generation, Results fold only when generation, revision and Work match, and budgets are charged once at allocation.
- Observation and legacy writers can no longer move a record out of a human wait, which ended a comment loop on budget exhaustion.
- Remote operation statuses change only through the operation table's rows, with lifecycle rows fired on confirmed or failed operations.
- A human resume relaunches exhausted provisioning, and publish retries and re-plans get fresh operation ids so the store never refuses a commit.
- Documents that a paused, stale, exhausted provisioning wait is stuck until a table decision.
- Dossier decisions and provisioning run on table verbs, the `destination_writes` flag and pre-fork proposals are removed, and `force-develop` is retired.
- Adds the trusted `handoff.yml` workflow for debug cleanup, internal PR closure and the submission package, and accepts `submit-upstream` and `retract-pr`.
- Renders model-written text in the package as code, treats handoff launches without a receipt as failed attempts, and hardens the workflow checks and token handling.
- Neutralizes mentions regardless of Markdown context, tells the human to withdraw rather than edit the series, and hardens package discovery.
- Inserts a word joiner after every at sign not preceded by a letter or digit, closing the character-reference mention bypass.
- Adds this log with one entry per commit of the current work and an AGENTS.md rule that every commit adds its own entry.
- Reduces every entry of this log to what changed and how, without subject or date, and updates the AGENTS.md rule to match.
- Adds the contribution guidelines (pull request templates, contributing instructions, measured commit conventions with measurable rules, and reviewers of the changed paths) to dossier schema version 2, and makes the research gate require them, with "none found" admitted only with the record of the search.
- Carries the dossier's measurable commit rules in the Work payload and makes the trusted worker gate reject a series whose non-debug commits break them; the worker is told to follow the contributing instructions, commit conventions and reviewer expectations.
- Moves development to riscv64-dev and builds riscv64 at submit-upstream from a model-reviewed series that trusted code checks for the same tree, the commit rules and the template sections, under an exact-head lease and never while an upstream PR is open from it; the development PR is never closed, and a record that names another development branch is a processing error of that contribution.
- Makes the build of `riscv64` refuse to write it while a pull request of the fork is open from it, while `riscv64-dev` is missing, or while the record does not develop on `riscv64-dev`, waiting for a human with the reason through `require_branch_intervention`.
- Validates every commit of the reviewed series against the base, its touched paths, and the blobs of the approved series, admits only the App's identity or the approved commits' own attribution trailers in the submission check and the worker gate, reads Markdown headings without a backtracking pattern, and refuses a branch read that GitHub redirected to another branch.
- Splits the submission into a rewrite Work, checked by trusted code before anything else, and a separate review Work that reviews exactly the rewritten series and text and blocks on failure, treats an unusable Result of either as a Work retry, returns an expired rewrite to a fresh rewrite, and states that no upstream text widens the trusted gates.
- Adds tests of the live gate record in the shape of its hand edit (developing on `riscv64-dev` with the human-opened development PR #2), covering its validity without any migration, the gate's observation, the review reads of PR #2, and the submission with the build guard.
- Dispatches the required CI workflow on a rebuilt `riscv64` head when it accepts `workflow_dispatch` and asks a human when clean-head CI cannot run or does not complete in a bounded wait, records the upstream PR head as the head upstream review works on, checks the reviewed series' artifact before any token is minted, and requires exactly one publication artifact per worker run.
- Points the live ciso8601 record at riscv64-dev and development PR 2 by a one-off, operator-authorized edit of its state.
- Attribution trailers are matched on the NFKC, case-folded form of each line with hyphen-like characters, the underscore, and colon-like characters folded, the title counts as a trailer, and a white-space-led line continuing an attribution trailer is refused; tests cover each lookalike.
- The submission check refuses a series of more than 50 commits before any per-commit validation, counting its mbox before the rebuild and the rebuilt commits before validating them; a test bounds the time and asserts no commit is validated.
- The submission check requires the tree of every reviewed commit to be a tree of the approved series without its debug commits, later in that series than the previous one, so squashing and rewording pass while reordering, splitting into new trees, and resurrected content are refused; the worker instructions and the readings to confirm say so.
- The worker's publish job unsets the step's read token before it checks a submission rewrite or review, so those checks run without any token as documented.
- The handoff's series step now rebuilds and checks the reviewed series anonymously before any token is minted, and after the mint the branch step only verifies the digest, head, and tree of that prepared repository and pushes; the CI dispatch names `refs/heads/riscv64` and uses a separate `actions: write` token minted only when the clean head needs its own CI.
- Repairs the docstring of the pending record migrations in state.py, which had lost a clause and now lists the four migrations in order.
- The expiry of a submission rewrite follows the effective retention of the worker's publication artifact, which the controller's workflow now passes to the tick from the repository variable `GH_AW_DEFAULT_ARTIFACT_RETENTION_DAYS` (30 days when unset), and the readings record the repository retention limit the tick cannot see.
- CI evidence lists the jobs of a run sorted by job id, so observing the same run again no longer rewrites the evidence file on every tick.
- The underscore is no longer folded to a hyphen when attribution trailers are matched, so a body line such as `order_by: x` is not refused as a trailer.
- `lifecycle check` now reports a table mutation that breaks the settled review, repair, first-patch and resume decisions, and the known gap listing those missed violations is removed.
- A resume from `parked.idle` that names only `class` or only `paths` is refused when it is posted and changes nothing, since such an override could never admit development.
- Development follows the lifecycle table: patch Results, publish-only retries (a lost retry included), dispatch and Work recovery, and the observation of `development.waiting_ci` take the table's rows, a worker `no_change` takes `request_ci_rerun` and waits for newer CI, the Work deadline is removed, and a record migration rewrites the development states the table does not have.
- A fork head that moves while development Work is due now takes `record_head_change` from `development.fix_needed` to `development.waiting_ci`, a new row of the table, so the observation records the new head at a new revision and waits for its CI instead of deferring the Work.
- A dispatcher relaunch for the submission rewrite or review Work is no longer dropped in a tick that observes CI: the reconciler keeps a relaunch for every record that still holds its Work in a working phase or in `handoff.agent_running` or `handoff.reviewing`, so `retry_dispatch` and `exhaust_dispatch_recovery` apply to that Work as in development.
- Work that an allocation row names under a graph that already returned a Result or is terminal in the queue no longer pauses the contribution: the controller takes `allocate_work_retry` for a fresh graph at a new revision in the same tick, or `exhaust_work_recovery` once `work_recovery` or `work_total` is spent.
- The status page now renders its table as HTML with a closed `<details>` event log under each contribution, newest event first, showing time, verb, cause, states, and revision with links to the runs, commits, pull requests, CI jobs, operations, and evidence that committed state resolves, styled for both color schemes in `docs/_sass/custom/custom.scss`.
- The status ledger now posts a tracking-issue entry only for an event the lifecycle table marks as needing a human (entering or re-revisioning a `gate`, `human_wait`, or `locked` state, setting `paused`, a park, a terminal state, or `record_reminder`) and reports every other event as `status_page_only`; `record_explanation` is linked from the website event log instead of quoted on the issue.
- The state store no longer stages an evidence record that differs from the committed one only in its collection time, so an unchanged CI observation makes no state commit.
- Upstream review and release now follow the lifecycle table: the observation takes `record_merge`, `record_pr_closed_unmerged`, `record_head_change`, `record_explanation`, `record_actionable_review`, and `record_upstream_ci_failure` (once per head and run) from `upstream_review.waiting_ci`, revision Results are folded by `record_revision_publish_success`, `require_reviewer_answer`, `reject_patch_proposal`, and the publish retry rows, and `release_wait.idle` takes `verify_release`, `require_release_intervention`, or `record_release_incomplete` from PyPI metadata and tag provenance. The legacy upstream review fold, its publish retry, `compat.observe_head`/`observe_status`, the legacy pause and command paths, and the states `upstream_review.idle` and `upstream_review.waiting_capacity` are removed.
- `record_revision_publish_success` now records in `upstream_pr.head_sha` the head the publisher read back on `riscv64` and bumps the revision, so the observation no longer writes that head outside the table and the next revision Work is a new Work graph. In upstream review an uncertain publication, whose push was not read back, is now a failed publication (`schedule_publish_retry`), and a published Result that names no head read back is refused.
- The contribution record schema is strict now: every field, the `budget` counts (`reruns` among them), `pending_human_action.counter`, and the Work identity fields (`feedback_evidence_ids` among them) are required, `blocked_reason` is gone, and the `phase`, `activity`, and counter enums are generated from the lifecycle table; the controller adds the fields an older record lacks at the values the pipeline read for them in one evented, exact-shape record migration (`state.migrate_record_fields`), which replaces the earlier record migrations.
